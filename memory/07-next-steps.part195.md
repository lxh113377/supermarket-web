## 2026-10-26 — 四次同一个动作丢末行换行，第五次由谁拦？

- 计数（全部一手、本会话内）：ProductCard / OrderConfirmPage / ServiceFormPage 三件被 CI 的
  verify:eol E7 抓到（= cb20506 那笔 gates 红，deploy 被 needs 跳过 ⇒ 线上落后四笔）；
  DashboardTab 第四件被本地 npm run verify 全链抓到。四次同一个动作：
  「read 全文 → join(换行符) → write 全文」—— join 把「最后一个换行符之后的空串」丢了。
- 前三次靠 CI、第四次靠本地全链，都**已经提交之后**才发现。E7 判的是已提交的 blob，
  所以它的时机天然晚一步；而 pre-commit 五条腿里没有行尾腿 —— 这就是机制缺口。
- 收口（95fed8f）：给 check-staged-syntax.mjs 加一条独立腿，判**暂存区 blob** 的末字节是否 LF。
  三个口径细节：
  ① 扩展名面取自 .gitattributes 里钉成 text 的那些，**不含 binary 件** —— 它们字节里的 0A
     是内容不是行尾，判它们等于把内容当行尾（verify:eol 头注里那 100 件二进制同族教训）；
  ② 空件豁免（与 E7 同口径：空文件没有「最后一行」可言）；
  ③ **独立于语法腿** —— .ts/.tsx 一直是 node --check 的盲区（本闸长期声明这一点），
     而本轮那四件全是 .tsx/.ts：正落在旧盲区里，所以「盲区」不等于「不能判」。
- 夹具 stagedSyntax.test.js 6 → 9 条：正向（缺 LF 判红并点名）、反向半边（补齐后同一件翻绿，
  证明红因就是那一个字节）、边界（空件豁免 + 好件不误伤）。**加这条自证是因为本轮正在修的
  就是「写了不生效」那一族** —— 加一条没人验的腿等于再埋一个第五次。
- 顺带一条本轮反复用到的判读纪律：**零输出不等于通过**。我给这条腿做合成仓自证时，
  第一次跑出 rc=0 + 零输出 —— 那不是「判过了没问题」，是 main() 压根没跑
  （isCli 路径判定在合成目录下不成立）。正解是改用仓内常驻夹具（它的 run() 走绝对路径 +
  cliLeg 守卫），而不是把空输出读成绿。
