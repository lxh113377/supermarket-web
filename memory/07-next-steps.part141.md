# 07-next-steps · 第六十八轮 · 机制性根因（从 part139 原样迁出）

## 顺手挖到的第二条机制性根因（比本轮四项更值钱的沉淀）

`--update` **不是自洽的一趟**：README 的「门禁一览」由它生成，而那份 README 又是它的取数面，
登记册却在重写 README **之前**就落盘 ⇒ counts 天生比现状**少它刚给自己加的那些行**。
本轮加一个别名后实测：`--update` 自称 GATE-PASS，紧跟 `--check` 回 `mentions 册上 278 → 现算 279`。
**这就是"台账漂移"第 4 次复发的机制**——第六十七轮的"先写正文再 `--update`"只缩小窗口，
没关掉"生成器把自己的输出算进取数面"这一半。修法：写 README → 重新取面 → 再写登记册。
反例腿建在一次性夹具仓里（`tests/docCommands.test.js`），并配"删掉重取那步 ⇒ 必须当场复现漂移"的变异腿。
