## 2026-10-26 — verify:eol E7 点名三件缺末行换行（cb20506 的 gates 红）

- 红因：三条都是我用「read 全文 → `join('\n')` → write 全文」重写过的文件 ——
  **join 会把「最后一个换行符之后的空串」丢掉**，于是末行换行消失。一个动作批量制造三处
  同类缺陷，不是三次偶然。
- 更该记的是**为什么本地没抓到**：我把「提交前四连跑」执行成 lint + typecheck + 受影响单测 +
  全量 vitest，而 `verify:eol` 既不在那四步里、也不在 pre-commit 钩子里（钩子只有
  staged-syntax / memory-volume / memory-pointer-sync）。它只在 CI gates 与本地 `npm run verify`
  聚合链里 —— 而我为了赶部署没跑全链。
- 纪律修正（写进本仓口径）：**推之前跑 `npm run verify`（全链 45 段），不是跑一个自己挑的子集**。
  part188 已记过一次同族（测试文件自身的 lint 债），这是第二次 —— 同一族病的成因从来不是
  「不知道有这条判据」，而是「赶时间时把子集当全集」。
- 判据口径确认：E7 读 **blob 侧**，所以补完末行换行后本地仍报红、**提交后才 PASS**（实测）。
  这不是判据坏，恰恰是它对：它断言的是 git 决定的量，不随本机 core.autocrlf 变。
- 同轮另两处登记面漂移，都按判据给的处置办、不手抄不放宽：
  ① `check:doc-commands` counts 过期（385→387 / 370→372，因我改了文档）⇒ 跑 `--update` 重生；
  ② 新卷 part193 写到 3538B 撞 V4「出生须 ≤3072B（留 25% 余量）」⇒ **现在就拆两卷**
     （本卷 194 就是拆出来的下半），而不是等提交前压字节 —— 这正是 part187 那条「压措辞续命」
     恒真放行的反面做法。
