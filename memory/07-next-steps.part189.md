# 07 分卷 189 —— 第 91 轮：三件「写了从未渲染」的签名设备（一手实测）

> CHANGELOG 同日条目为准；本卷记**判据看不见的缺陷**这一族的三条一手形态。

## 2026-10-26 — 「引用面改了、定义面没有」的第四、五、六次复发

- forest（第 90 轮）之后又抓到三条同族，全部**在生产包里静默失效**且构建零报错：
  ① `var(--brand-bar)` 六处引用、全站零定义 ⇒ 金线全透明。为什么第 90 轮那把对账闸抓不到：
     它的引用面正则只扫 `var(--t-[a-z0-9-]+)`，而这个变量名**不带 --t- 前缀** ⇒ 整条链在面外。
     治法不是补一个游离变量，而是改名 `--t-brand-bar` 进族 ⇒ 从此缺定义即判红（机制而非措辞）。
  ② `@keyframes shimmer` dist 出现 0 次：tailwind.config 里定义了，但 `animate-shimmer` 工具类
     全站使用 0 次 ⇒ Tailwind 不产出对应 keyframes，而 `.skeleton-shimmer` 直接写 `animation: shimmer`
     ⇒ 全站骨架屏纹丝不动。**Tailwind 的 keyframes 只在对应 animation 工具类被用到时才产出；
     手写 `animation: <name>` 引用的动画名必须自己确认它在产物里。**
  ③ `[class*='focus-visible:outline']:focus-visible{outline:none}` 特异性 (0,2,0) 压过全局环，
     而 TW3 的 `outline-2` 只给 width/color **不给 outline-style** ⇒ 挂该类名的 8 处控件键盘零焦点环。
     `layout.spec.ts` 只测「加入购物车」（未挂该类）⇒ 判据全绿而缺陷隐身（**取样面 ≠ 缺陷面**）。
     治法 = `:where()` 把特异性归零 + 自带在册环；组件真写了自定义环仍然赢。
- 三条共同点：**都是「写了」的那一侧生效失败**。grep 源码看不出来（那行确实存在），
  只有拿产物做「引用面 ⇄ 定义面 ⇄ 是否真被渲染」三向对账才看得见。
  候选判据（未做，见 part190 下一轮候选）。

## 2026-10-26 — 本轮两处自己踩到又自修的红（非放宽）

- 凑单文案把金额包进 `<b class=price-num>` ⇒ getByText 只取**直接子文本节点**，
  「再挑 ¥3.34 即可下单」被切成两截，minDeliveryGate:39 与 order-flow:74 当场红。
  正解 = 整句保持单文本节点，金额档由整行的 font-variant-numeric/颜色承载（已写进代码注释）。
- 首页货架「取前 8 件」是**截断型上限** ⇒ C2「每个上限都有登记行」判红（这条闸真的在守）。
  正解 = 进 limit-provenance 写清「8 = 1240px 容器实测不横向溢出的最大列数」，不是删判据。
- 体积三件超旧预算：按名册**既有机械规则**（实测 ×1.10 上取整 100B）重推导并逐条写归因；
  firstLoadCss 保持 `25 * 1024` 整数乘法形态（小数会静默断供治理器正则，见 part183）。
