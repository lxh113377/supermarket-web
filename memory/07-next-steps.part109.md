# 07 分卷 109 —— 第五十六轮踩坑 5–7（自卷 105 整条迁出）

> 拆卷原因：V4「出生即贴线」。坑 1–4（半成品/静态 import/值写进匹配串/负测前提）在卷 105，本卷是 5–7。
> 这三条同族：**反例的对象是"当前值"而不是"被测量本身"**，所以被测对象变好会把反例悄悄缴械。

5. **零余量地板落到 0 之后，"压到 0"不再构成干预**。`cliLegCoverage` 的反例原样是"把 `unguardedMax` 压到 0，
   拿真面 11 件欠账去撞出 rc=1"；R56-H2 把欠账清偿到 0 之后，同一动作实测 rc=0（`expected +0 to be 1`）。
   ⇒ 牙齿必须由**被测量**提供：改成在临时 `--dir` 植一条真裸腿（带 timeout 的 spawn、未接守卫）⇒ 欠账 0→1，判红照旧，
   且从此与真面欠账数无关。
6. **新增散文会让旧反例失去对象**。`piiInventory` 的 P9 反例用**非全局** `replace` 抹掉 `rate_limits.bucket`，
   本轮我在「已知缺口」第 4 条里又提了一次那个 token ⇒ 第一次抹掉后还剩一处 ⇒ P9 不再点名 ⇒ `expected true to be false`。
   ⇒ 反例的清除动作改成全局（`.replace(/rate_limits/g,'X')`），别靠"作者记得只写一次"。
7. **TS 判别式两连坑**：`fail()` 返回对象里的 `code` 被宽化成 `number`，所以 `if (r.code !== 0)` **不是窄化**（实测 TS2339）；
   换成 `ok: true | ok: false` 之后，`if (!r.ok)` 在本仓 `strict:false`（关 strictNullChecks）下**同样不窄化**，
   只有 `if (r.ok === false)` 走判别式等值窄化。两处都留了注释，因为写的人一定会再犯。
