## 第 91 轮第三笔：购物袋挂缩略图（同一个坑踩两次的一手记录）

- 目检抓到的最后一处廉价点：商城卡 / 详情页灯箱 / 首页货架都有图，**唯独购物袋是纯文字清单**
  —— 而它是转化链上最贵的一屏。补图后台面复用 --t-stage（与那三处同源），不引新形。
- **两次「写了不生效」都发生在我补这张图的三十行里**（与本轮铜条 / shimmer / 焦点环同族）：
  ① 用正则解 productId 猜序号 —— 实测购物车里的 id 形如 `p006`（补零三位），
     而 localStore 给 seed 补的 `_id` 是 `'p_' + order` —— **两条链不同形**，正则永不匹配，
     于是缩略图静默不渲染。构建照过、oxlint 照过、单测照过，只有去 DOM 数 `photos` 才看得见。
     正解 = 序号由父页查目录传入，且复用 CartPage 那次 getProducts()（价格漂移本来就要拉）=> 零额外请求。
  ② 修的时候又把 \\d 写成双反斜杠（源码里多一个反斜杠），同样永不匹配。同一个坑两次。
- **fail-safe 分支要单独测**：上一版探针在 `/#/cart -> /#/cart` 之间改 localStorage，
  同 hash 导航不重挂载 => 读到的是旧购物车，**测的根本不是目标分支**（还得出 photos=3 的假结论）。
  正解 = 新上下文先 goto 首页再写存储再进 /#/cart。实测：云端 D1 主键那条 hasPhoto:false
  （整块不渲染，不摆破图也不摆占位方块）、本地 id 那条 hasPhoto:true、brokenImgs:0、控制台 0 条。
- 教训合并成一条可复用的：**「id 形态」不是契约**。同一个语义（商品序号）在 seed / localStore /
  D1 三条链上有三种形态，任何「从 id 反推」的代码都必须有「推不出来就整块不出」的分支，
  并且那个分支要**单独造数据测一次**（同 hash 不重挂载，换上下文才测得到）。
