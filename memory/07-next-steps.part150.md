# 07-next-steps · 第七十轮 · 本轮自己踩的坑（下半）

> 接 `07-next-steps.part148.md`（上半）。同轮的交付回执 + 下一轮 P0 → `07-next-steps.part149.md`。
- **搬走"未采到"样本会制造新的绿色沉默**（本轮改造里最需要盯的一条）。
  一手：隔离 7 件 `NO_FCP` 之后，`report:live-perf` 由 `verdict=RED` 转 `GREEN rc=0`，
  但那个 GREEN 若无隔离读数，会被读成"顾客端性能达标了"，而真值是"有 7 件网络类失败被搬到别处"。
  ⇒ 判据那行必须同步把隔离件数并进**门面恒等式的第四项**：
  `入统计 + 未采到 + 产物不符 + 已隔离 == 取数面样本 + 隔离区样本`，并显式印"总恒等式 ✓"。
  ⇒ **任何"隔离 / 排除 / 过滤"型改动，都必须回头问：判据那行现在还看得见被移走的东西吗？**

- **复原后索引会变成幽灵声明**。一手：`--restore` 搬回全部样本后，若隔离区还留着 `INDEX.json`，
  判据那行会继续印「已隔离 7 件」而实际隔离区 0 件 ⇒ 同一批件被两个读数各数一遍。
  正解：隔离区空 ⇒ **撤索引**（不是删数据，是撤那份"现在有 N 件在这儿"的声明）；非空 ⇒ 重写计数。

- **`--dir` 注入点缺失会让夹具动真仓**。一手：隔离器第一版 CLI 没读 `--dir`，
  夹具第一次跑就把真 `.lighthouse/` 的 7 件搬走了，而夹具以为自己造的是合成目录。
  ⇒ **判据类脚本凡有"搬动"这类副作用，默认路径上只许读不许动**，必须带显式注入点。
  ⇒ 同族：`if (x) y() else z()` 这种单行无块写法在 `.mjs` 里是 SyntaxError（第一版就这么红的）。
