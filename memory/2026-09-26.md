## H5 localStore 读出口拷贝收口（N1，修一类不修一例）

【数据流假设】
来源: `src/localStore.ts:3` 是全站**唯一** import `./data/products-seed` 的文件（实测 `grep -rn "products-seed'" src/` 仅 1 命中）⇒ 种子数据的读出口边界就是 localStore；`getLocalCategories():73-75` 直返 `seedCategories` 模块引用，是 4 个数组读出口中唯一未过 `cloneArray` 的一个（`getLocalProducts:88,94`、`getLocalOrders:148`、`getLocalReviews:188` 均已 clone）。
流向: 消费者 = `src/db/products.ts:39` 与 `:57`（本地模式分类读出口）→ 上层 `useCategories`/管理端下拉/顾客端分类页。改动后仍返回同长度同元素数组，调用方零感知；`tests/` 下当前**无**任何 `getLocalCategories` 用例（实测 grep 0 命中）⇒ 本次要新建断言，否则改动静默。
结构: `Category[]`（`src/types.ts`），浅拷贝容器 `slice()` 即恢复"每次读都是新数组"语义；不深拷贝对象本体 —— 现有调用方只做 `setState` 与 `[...list].sort()`（第七轮实测），风险点是原地 `sort/push/splice` 污染整个会话的种子顺序，浅拷贝已足以切断；深拷贝会让每次读都重建对象，属过度设计。
异常: 若 `seedCategories` 因数据文件改动变成非数组（畸形种子），`cloneArray` 的 `Array.isArray(list) ? slice : []` 已兜底为 `[]`，与既有三个读出口行为一致；TS 类型不匹配则 typecheck 直接红，不会静默。

## H3 浏览器 spec 错误观察器产断言（N3 收口）

【数据流假设】
来源: `tests/e2e/smoke.spec.ts:16-18`（实测）把 `pageerror`/`console error` 只 `console.log` 到 stdout ⇒ 页面抛错 e2e 仍绿；同型出口在 `order-flow.spec.ts`、`product-detail.spec.ts` 各一份；已有正确形态在 `tests/e2e-stub/dashboard-cloud.spec.ts:35`（`page.on('pageerror', e => pageErrors.push(e.message))` + 末尾断言）。
流向: 新 helper `tests/e2e/helpers/watchErrors.ts` ← 被 3 个既有 spec import；`page.on('console'|'pageerror')` 收集 → `expect(errors).toEqual([])` 在 teardown 断言。Playwright 的 expect 失败即该 test 红，从而阻断 `deploy.needs=[..., e2e]`。
结构: 返回 `{ errors: string[], dispose(): void }`；白名单沿用 stub spec 的资源噪声口径（`favicon`/`net::ERR_FAILED` 类），白名单必须锚定具体串，禁泛化词（R236 第三条）。
异常: 若某页当前**已有**存量错误，接入即红 —— 处置是先如实记录并修复，禁止为凑绿放宽白名单（R263 先修判据不改数据，反之判据对时改的是代码）；helper 未 dispose 会跨用例串污染，故每个 spec 用 `test.afterEach` 收口。
