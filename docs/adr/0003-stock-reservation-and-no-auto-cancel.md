# ADR 0003: 下单即占库存，但不做超时自动砍单

- 状态：已采纳（2026-09-24 第二轮 A5 修订）

## 决策
1. 下单即占用有限库存（`stock >= 0`）；不限售项统一记 `stock = -1`，扣减 SQL 带 `AND stock >= 0` 守卫，
   避免把 -1 扣成负数变成"看起来还有货"。
2. D1 无跨语句事务 → 用「守卫式 UPDATE + 同请求内补偿」：任一 item 扣不到就回补此前已扣的项并整单拒绝；
   落库抛错（含幂等唯一冲突）同样回补。失败不再凭空少库存。
3. **不照抄** litemall `OrderUnpaidTask` / Saleor `checkout_cleaner` 的定时自动取消。

## 为什么不自动取消（本项目特有约束）
支付是**线下确认制**：顾客扫码转账 → 管理员手工置 paid。pending 超时既可能是跑单，也可能是"已转账待确认"。
定时砍单会误杀后者，且顾客侧订单查询页会显示"已取消"——错一次就损失一个真实客户。

## 采取的方案
新增只读 action `stalePendingReport`（不进 `ADMIN_WRITE_ACTIONS`）：按账龄列出超时 pending 单，
标记是否附付款截图（有截图 = 大概率待确认，应优先处理），并统计这些单占用了多少有限库存。
砍不砍由人决定，走既有 `updateOrderStatus`（同一条库存回补路径，不复制第二套逻辑）。

## 待条件成熟再评估
若接入真实支付回调（见报告 C4 资质门槛），"pending = 未支付"才成为可靠信号，届时可改为超时自动释放。
