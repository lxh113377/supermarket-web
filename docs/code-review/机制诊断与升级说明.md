# 代码审查机制诊断与升级说明（v1.0 → v2.0）

> 执行者：Code Review Expert（火眼眼）
> 日期：2026-08-23
> 背景：用户反馈「代码质量参差不齐，需建立系统审查机制」。经核查，机制**已存在**（2026-08-08 写的 v1.0 三件套），但**严重过时**——它停留在 CloudBase + 纯 JS 时代，从未随 2026-08-19 的 Cloudflare + TypeScript 大迁移更新，导致标准指导错配、反模式表失真、关键门禁缺失。本说明记录诊断结论与 v2.0 升级动作。

---

## 一、诊断结论：机制「有但失真」，这才是质量参差的根因

| 维度 | v1.0 现状 | 真实情况（2026-08-23） | 失真等级 |
|------|-----------|------------------------|----------|
| 语言栈 | 「项目尚未迁移 TS，靠 jsconfig + checkJs」 | 已是 **React 19 + TypeScript 7**（`src/auth.ts`、`src/cart.ts`、`tsc --noEmit` 可用） | 🔴 事实错误 |
| 版本控制 | 「阶段 0：当前没有 .git 仓库」 | **已有 git 且有提交**（`git log` 可见） | 🔴 事实错误 |
| 后端栈 | 全文「CloudBase / 云函数 / NoSQL 注入 / 集合安全规则」 | 实为 **Cloudflare Pages Functions + D1（SQLite，参数化查询）** | 🔴 指导错配 |
| db 模块 | §4.1/§4.2 列「上帝模块 + import-time 副作用」为开放反模式 | **已拆成 `src/db/` 子模块修复**（提交 `951ec10`） | 🟡 已修复未更新 |
| 字段白名单 | §4.7「仅商品写入」 | **已扩到订单/评价/提交**（提交 `935f393`） | 🟡 已修复未更新 |
| Lint 门禁 | §4.8「仅 3 条规则，门禁过弱」 | 根 `.oxlintrc.json` 已有 11 条规则（含 `react/rules-of-hooks: error`） | 🟡 已修复未更新 |
| 死代码 | §4.4「auth.js tcb-api 兜底 URL」 | **已删除**（提交 `688458c`） | 🟡 已修复未更新 |
| **CI 门禁** | 流程门禁表列 lint/test/build | **缺 `typecheck`**（TS 项目最关键的门） | 🔴 机制缺口 |
| **明文密钥** | 只谈 CloudBase env | **`wrangler.toml` 被 git 跟踪且明文 `ADMIN_KEY="supermarket-admin-****"`**（`git ls-files` 可见，`.gitignore` 仅忽略 `.wrangler/`） | 🔴 P0 真实风险，标准未覆盖 |
| 引用断裂 | PR 模板 / 流程文档引用 `REVIEW_CHECKLIST.md` | 实际文件在 `docs/REVIEW_CHECKLIST.md`，**路径不对导致引用失效** | 🟡 机制断裂 |

**核心判断**：不是「没有机制」，而是「机制写了一次就没人维护，架构迁移后变成了误导性的文档」。最危险的是——它会教现在的reviewer 去查「NoSQL 注入」「CloudBase 集合安全规则」，却漏掉「明文密钥入库」「类型错误溜过 CI」这两个真正要命的问题。

1. **就地重写 `docs/CODE_REVIEW_STANDARD.md`** → 技术栈改为 Cloudflare+D1+React19+TS；重写 §3 栈专项；§4 反模式表按真实状态重排（已修复项标注「✅ 已在 vX 修复」，新增当前真实风险）。

3. **就地重写 `docs/REVIEW_CHECKLIST.md`** → 栈快查改 D1/Cloudflare/TS；加 typecheck + 明文密钥检查；删 NoSQL/CloudBase 错配项。
4. **修复 `.github/PULL_REQUEST_TEMPLATE.md`** → `REVIEW_CHECKLIST.md` → `docs/REVIEW_CHECKLIST.md`；自测清单加 `npm run typecheck`。
5. **修复 `.github/workflows/ci.yml`** → 增加 `npm run typecheck` 步骤（关闭类型错误溜过 CI 的缺口）。

## 四、给 owner 的后续建议（非本次文档范围，但建议尽快处理）

- **R1 是真正的安全事件级问题**：明文管理密钥已进 git 历史。即便现在改 secret，历史 commit 里仍有明文。建议轮换 `ADMIN_KEY` 值，并将新值仅存于 Cloudflare secret。
- **建立「架构迁移即同步审查标准」的纪律**：本次失真源于「大改代码却不改文档」。建议在流程里加一条铁律——任何涉及技术栈/部署架构的 PR，必须同步更新 `docs/CODE_REVIEW_*` 与 `AGENTS.md`。
- **每季度复盘标准**（流程文档已写，但需真正执行）：把新出现的反模式沉淀进 §4，把已修复的移出。

> 三件套与 PR 模板、CI 现已升级为 v2.0 并互相引用一致。下一步建议挑 R1（明文密钥）立即处置，优先级高于任何新功能。
