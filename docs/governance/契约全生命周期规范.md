# 契约全生命周期规范

> 登记册 `docs/governance/registry.json`（schema chaoshi-governance-registry-v1）。本文件每处 [registry:...] 引用对它做存在性对账；下列节点 id 逐字取自该册，不另造、不改名。

## 1. 目的与适用范围

契约 = 三份生成物 + 白名单：`docs/api-contract.json`（/web 35、/pub 9 个 action；源 `functions/lib/backend.js`）、`docs/api-response-contract.json`（47 条；源 `scripts/verify-backend.mjs` 真实流量）、`docs/openapi.json`（44 条 path，派生自契约），加 `functions/lib/shared.js` 的字段白名单。适用：action、请求/响应字段、白名单字段的增删改。不适用：纯样式、纯文案、纯构建配置。

## 2. 五阶段总览

| 阶段 | 入口条件 | 准出条件 | 证据件 |
|---|---|---|---|
| 起草 | 需求落到 action 粒度 | 三生成物重算 diff 干净；上限与新 chunk 各在册有行 | 三生成物；`docs/doc-commands.json` broken=0 |
| 审核 | 起草自检绿 | 破坏判定 rc=0，或每条破坏在 `.ci/contract.json` 带 untilUtc 与可证伪理由 | check-contract-diff.mjs 五类 BREAKAGE_KINDS |
| 签署 | 审核签字 + 豁免登记齐 | 生成物与源码同笔；CI 必需 6 job 全绿；发布面合并 | `.ci/contract.json` requiredJobs = [gates, browser-install, e2e, e2e-cloud-stub, visual, deploy] |

| 归档 | 冻结且不再被现行实现引用 | 快照可由提交复算并召回 | 提交面；check-contract-diff.mjs 基线腿 |

## 4. 契约风险预警机制

三档，信号一律写成可复算的判据（点名命令或登记件），不写形容词。

- [registry:lc-risk-t1] 提示（黄）。信号 = `npm run verify` 任一腿红，或本文件命令在 doc-commands.json 的 broken > 0。阈值 = 单笔 ≥1 条。处置 = 重算三生成物并重跑该腿。窗口 = 1 个工作日。责任人 = 起草人。升级 = 2 个工作日未闭合 → t2。
- [registry:lc-risk-t2] 严重（橙）。信号 = `scripts/check-contract-diff.mjs` rc=1（未登记破坏）或 rc=2（基线取不到），或响应形状对账出现未具名漂移。阈值 = rc≠0 且 `.ci/contract.json` 无对应 contractBreakageExceptions（或已过期）。处置 = 补登记（untilUtc+可证伪理由）或回退该笔。窗口 = 4 小时（发布前）。责任人 = 风险评审人。升级 = 线上形状不一致 → t3。
- [registry:lc-risk-t3] 阻断（红）。信号 = d1-write-quota.json 的 peakRowsWritten×callsPerDayAtPeak 越过 daily_rows_written_free（21×4,761=99,981 对 100,000，余 19 行/日=0.019%），或 `npm run verify:volume` 破红线（4,096 B / 40,960 B，现值 3,132 B）。阈值 = 余量 ≤ 0 或红线被破。处置 = 停写并在当日 UTC 日界前降峰值。窗口 = 立即。责任人 = 容量 owner + 契约官。升级 = 连续 2 个日界未收口 → 密钥 owner 拍板。

## 6. 缺口与替代方案

- 现盘**没有** `docs/governance/registry.json`（HEAD f2410b3 枚举命中 0）。替代 = 本文件按目标形态引用 [registry:...]，该册落地后由 `npm run verify:governance`（`node scripts/check-governance-framework.mjs`）守；落地前不宣称已生效。
- `.ci/contract.json` 现值**没有** contractBreakageExceptions 键（顶层现存 9 键）。替代 = 空册即无豁免，首次与改动同笔加键。
- **没有**独立契约快照目录（`docs/archive` 无契约命名册）。替代 = 提交面 + 基线腿逐版复算。
- **没有**签名/密钥面的机器回执（ADMIN_KEY 权威 = Pages secret 与本地 `.dev.vars`）。替代 = 户内铁律 + 线上 login 实测。
- **没有**配额日账机器件（write-quota 为静态峰值，线上读数另挂 d1-remote-usage.json，龄阈 7 天）。替代 = 龄缺件按「未观测」处理。
- `docs/**` **不在**交付主张门禁取数面（check-delivery-claims.mjs 指向上级 deliverables）。替代 = 本文件零交付主张词。

## 7. 撤销条件

1. `docs/governance/registry.json` 不再以 chaoshi-governance-registry-v1 为 schema，或本文件 13 个生命周期节点 id 与 3 个风险档位 id 被合并/改名 ⇒ 全部 [registry:...] 引用失效。
2. 三份契约归一为单处真相源 ⇒ 第 1 节的契约定义退化。
3. 五阶段被替换为更少阶段 ⇒ 表中节点失去对应阶段。
4. 三档预警被 `docs/limit-provenance.md` 与 `docs/d1-write-quota.json` 内联吸收，独立档位不再被读。
5. `npm run verify:governance` 或 `node scripts/check-governance-framework.mjs` 不再在册 ⇒ 第 5 节缺一条腿。
6. 本文件与 `docs/doc-commands.json` 的 broken 计数持续不一致且无人复算。
撤销动作 = 同笔删除本文件或改指新册，并在登记册注销被撤节点；不得只改文字留下悬空 id。
